③ The FGSM Attack — Computing Adversarial Perturbation

xadv = x + ε × sign( ∇x L(θ, x, y) )
x = original input (30 normalised features)  ·  ε = perturbation budget (how far we can move the input)  ·  ∇x L = gradient of loss w.r.t. the input (not the weights)

During training: compute ∇θ L — gradient w.r.t. weights — step to reduce loss
During FGSM attack: compute ∇x L — gradient w.r.t. input — step to increase loss
Step 1 — Enable input gradient
requires_grad = True
Tell PyTorch to track gradient through the input tensor, not just the weights
x_adv = x.clone() .requires_grad_(True)
Step 2 — Forward + backward
Compute ∇x L
Run forward pass → compute loss → backpropagate. Gradient now sits in x_adv.grad
out = model(x_adv) loss = criterion(out, y) loss.backward() # x_adv.grad is now ∇_x L
Step 3 — Perturbation step
x_adv = x + ε·sign(grad)
Take the sign of each gradient component (+1 or −1) and step by ε. All 30 features perturbed in one shot.
delta = ε * x_adv.grad.sign() x_adv = x_adv.detach() + delta

⑥ Key Finding

🔴 CRITICAL — MITRE ATLAS AML.T0031 (Evade ML Model)
  • A model with 97.4% clean accuracy is reduced to 58.8% (near-random) at ε=0.30 — in a single gradient step, no library required.
  • The perturbation is mathematically targeted: it moves every feature in exactly the direction that increases the loss — not random noise, which would require much larger magnitudes to have the same effect.
  • This attack was computed without any adversarial library — just PyTorch's built-in loss.backward() and grad.sign(). Any differentiable model is vulnerable.
  • Production relevance: a medical diagnostic model, fraud detector, or malware classifier is subject to the same attack if an adversary can craft inputs. FGSM is the foundation — PGD (Exercise 6.5.2) runs this iteratively for much stronger results.
  • Mitigation: adversarial training (retrain on adversarial examples), input preprocessing, certified defences (randomised smoothing).
