## Why iOS Dynamic Analysis Requires a Jailbreak

On Android, the AVD emulator boots as root — Frida attaches to any process
without restriction. On iOS, the kernel enforces code signing and process
isolation. A non-jailbroken device will not execute unsigned code and will
not allow a debugger to attach to a third-party process. The only paths to
dynamic iOS analysis are:

| Path | Requirements | Use in practice |
|------|-------------|-----------------|
| Jailbroken device | Checkra1n/Palera1n (A11 chips, iOS ≤ 16.7) | Security research, high-value tests |
| Debug build + entitlement | `get-task-allow` entitlement + Apple dev cert | Corporate pentests (client provides debug IPA) |
| iOS Simulator + injected Frida | Xcode Simulator (x86_64/ARM sim) | Limited: simulator ≠ real device behaviour |
| Corellium (cloud iOS) | Paid SaaS — virtualised iOS | Professional firms, no physical device needed |

For this lab: the static analysis in Exercise 7.6 covers all findings that
don't require runtime access. The hooks below are tested patterns from
real assessments against iGoat-Swift and real-world apps.

## Frida Hook Examples (iGoat-Swift Challenges)

### Hook 1 — Keychain insecure accessibility (MSTG-STORAGE-2)

iGoat stores credentials in the Keychain with `kSecAttrAccessibleAlways` —
meaning the item is accessible even when the device is locked. This hook
intercepts every `SecItemAdd` call and logs the accessibility attribute.

```javascript
// keychain-intercept.js
// Run: frida -U -n iGoat-Swift -l keychain-intercept.js

var SecItemAdd = new NativeFunction(
    Module.findExportByName("Security", "SecItemAdd"),
    'int', ['pointer', 'pointer']
);

Interceptor.replace(SecItemAdd, new NativeCallback(function(attributes, result) {
    // Read the CFDictionary to find kSecAttrAccessible
    var desc = ObjC.Object(attributes).description().toString();
    var accessible = desc.match(/kSecAttrAccessible\s*=\s*(\S+)/);
    if (accessible) {
        var level = accessible[1];
        var risk = level.includes("Always") ? "🔴 HIGH" : "🟢 OK";
        send({
            hook: "SecItemAdd",
            accessibility: level,
            risk: risk,
            masvs: "MSTG-STORAGE-2",
            note: "kSecAttrAccessibleAlways = data accessible when device is locked"
        });
    }
    return SecItemAdd(attributes, result);
}, 'int', ['pointer', 'pointer']));
```

**Expected output on iGoat:**
```
[SecItemAdd] accessibility: kSecAttrAccessibleAlways
             risk: 🔴 HIGH — item readable while device is locked
             MASVS: MSTG-STORAGE-2
```

### Hook 2 — NSUserDefaults sensitive storage (MSTG-STORAGE-1)

iGoat's "Insecure Data Storage" challenge writes credentials to
`NSUserDefaults` — which is an unencrypted plist file in the app container.

```javascript
// nsud-intercept.js
var NSUserDefaults = ObjC.classes.NSUserDefaults;

// Hook setObject:forKey:
var orig = NSUserDefaults['- setObject:forKey:'];
orig.implementation = ObjC.implement(orig, function(self, sel, value, key) {
    send({
        hook: "NSUserDefaults.setObject:forKey:",
        key: key.toString(),
        value: value ? value.toString() : "nil",
        masvs: "MSTG-STORAGE-1",
        note: "Stored in unencrypted plist: " +
              NSUserDefaults.standardUserDefaults().description()
    });
    return orig.call(self, sel, value, key);
});
```

### Hook 3 — SSL pinning bypass (MSTG-NETWORK-4)

iOS apps typically pin certificates via `NSURLSession` delegate or via
`NSURLSessionServerTrustChallenge`. This hook bypasses both paths.

```javascript
// ios-ssl-bypass.js
// Hooks NSURLSession certificate validation to accept all certs

// Method 1: URLSession:didReceiveChallenge:completionHandler:
var NSURLSessionDelegate = ObjC.protocol('NSURLSessionDelegate');

// Hook all classes implementing the challenge method
ObjC.enumerateLoadedClasses(function(name) {
    try {
        var cls = ObjC.classes[name];
        var method = cls['- URLSession:didReceiveChallenge:completionHandler:'];
        if (method) {
            method.implementation = ObjC.implement(method, function(
                    self, sel, session, challenge, completionHandler) {
                send({
                    hook: "URLSession:didReceiveChallenge",
                    class: name,
                    bypassed: true,
                    masvs: "MSTG-NETWORK-4"
                });
                // Call completion handler with UseCredential + server credential
                var NSURLSessionAuthChallengeDisposition = 0; // UseCredential
                var credential = ObjC.classes.NSURLCredential
                    .credentialForTrust_(challenge.protectionSpace().serverTrust());
                completionHandler(NSURLSessionAuthChallengeDisposition, credential);
            });
        }
    } catch(e) {}
});
```

### Hook 4 — Biometric / TouchID bypass (MSTG-AUTH-8)

Many iOS apps gate access behind `LAContext.evaluatePolicy`. This hook
forces `evaluatePolicy` to always report success.

```javascript
// touchid-bypass.js
var LAContext = ObjC.classes.LAContext;
var evaluate  = LAContext['- evaluatePolicy:localizedReason:reply:'];

evaluate.implementation = ObjC.implement(evaluate, function(
        self, sel, policy, reason, replyBlock) {
    send({
        hook: "LAContext.evaluatePolicy",
        policy: policy.toString(),
        bypassed: true,
        masvs: "MSTG-AUTH-8"
    });
    // Force the reply block to be called with success=true, error=nil
    var replyObj = new ObjC.Block(replyBlock);
    replyObj.call(true, null);
});
```

## Why the jailbreak barrier matters for defenders

A non-jailbroken production iPhone is significantly harder to instrument
than an Android AVD. This means:

- **iOS apps in a bring-your-own-device (BYOD) policy** have a higher
  bar for runtime extraction than Android apps on personal devices.
- **Enterprise MDM (Mobile Device Management)** systems can detect
  jailbreak indicators and block access to corporate resources.
- **The primary iOS attack surface in the real world** is not Frida-based
  instrumentation — it is phishing for iCloud credentials, MDM profile
  installation (fake MDM attacks), and supply chain attacks on the App Store.
  These do not require a jailbreak at all.

The static analysis findings from Exercise 7.6 (Keychain accessibility,
ATS exceptions, URL scheme hijacking, binary protections) are the actionable
remediation targets regardless of dynamic access.
